# 挙動と保証

このページは，この crate が何を保証するか，そして同じくらい重要な点として，
**その保証がどこで途切れるか**を述べます．

## ルーティング

target が一致したロガーはすべてレコードを受け取ります．
どれも一致しなかった場合，レコードはフォールバックに渡されますが，
フォールバック側が拒否することもあります．
`set_fallback` は任意の `log::Log` を受け取るため，
ディスパッチャは渡す前にフォールバックの `enabled` を確認します．

## stdout への出力

レコードを受理したロガーはすべて stdout に出力します．
したがって2つのロガーが受理したレコードは2回表示されます．
`CustomLogger::with_stdout(false)` はそのロガーの stdout 出力だけを止め，
ファイル出力には影響しません．

## 追記のみ

ログファイルは追記モードで開き，ハンドルはロガーの生存期間中保持されます．
既存の内容が切り詰められることはなく，
前回の実行のログがロガーのせいで消えることはありません．

## エスケープ

各行は `serde_json` で組み立てるため，メッセージ中の引用符・バックスラッシュ・改行は
エスケープされたままになります．どの行も単独でパースでき，
これが JSON Lines 形式を実用的にしています．

## プロセス内での行単位の原子性

同じパスを指すロガーは1つのファイルハンドルと1つのロックを共有するため，
レコードが混ざり合うことはありません．

パスの同一性は「canonicalize した親ディレクトリ + 与えられたファイル名」で判定します．
以下はそれぞれ**別のハンドル**になり，保証の対象外です．

- 同じファイルへのシンボリックリンク
- 同じファイルへのハードリンク
- 大文字小文字を区別しないファイルシステム上での，大小文字違いの名前
- 同じファイルに追記する**別プロセス**

## ローテーション対応

キャッシュしたハンドルは，そのパスが現在指しているファイルと同一か検証されます．
そのため `logrotate` がファイルを退避させた後に作られたロガーは，
古いハンドルを引き継がず新しいファイルを開きます．

すでに開いていたロガーは，開いたファイルへ書き続けます（保持している fd の通常の挙動です）．
ファイルの同一性判定は Unix でのみ利用できます．
それ以外の環境では，置き換えられたファイルのハンドルは，
それを保持するロガーがすべて破棄されるまで残ります．

## I/O エラーで panic しない

開けない・書けない・flush できないログファイルは stderr に報告され，
ロガーはプログラムを落とさずに stdout 出力へ degrade します．
poison したロックは，出力を恒久的に止めるのではなく回復します．

ただしこれは，crate 全体が panic しないという主張ではありません．
利用者が渡した値の `Display` 実装が panic する場合は，
この crate に届く前の整形時点で panic します．
